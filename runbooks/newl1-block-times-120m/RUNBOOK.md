# NewL1 120M block-time capture: runbook for the remote machine

You are the agent that runs this measurement on this machine. Follow the steps
in order. It times NewL1's block executor on 67 prebuilt blocks, each 120M gas
filled with one expensive operation (a precompile or an arithmetic opcode). Every
block runs 57 times across 8 fresh worker sessions, and the median of the 40
timed runs is the result. The same blocks were timed on a Ryzen 9 9950X, and the
report compares the two machines. Timing is the product, so the machine must stay
quiet and the pinned inputs must not change.

## 0. Rules

- Do not edit any file in the `benchmarkoor` or `bnbchain-newL1` checkouts. The
  driver aborts on local changes.
- Do not push, commit, rebase, or open PRs anywhere.
- Do not pin CPUs, change the cpufreq governor, disable boost, or set CPU limits.
  The measurement runs unpinned on purpose. Record the host state only.
- Do not run other heavy work while the capture runs. That includes builds,
  other containers, browsers, and indexing.
- Do not delete or rename anything under the run home.
- Do not change `campaign.env` after the first start.
- If something fails and section 6 does not cover it, stop. Report the exact
  command, exit status, and log tail. Do not improvise a fix.

uname -m                     # required: x86_64

## 3. Setup

```bash
export WORK_DIR="$HOME/newl1-block-times"      # any path with >= 30 GB free
mkdir -p "$WORK_DIR" && cd "$WORK_DIR"

# Driver, blocks, and reference timings. Check out the commit that last changed
# this runbook, so later develop commits can't change the driver under you.
git clone -b develop https://github.com/weiihann/benchmarkoor
git -C benchmarkoor checkout --detach "$(git -C benchmarkoor log -1 --format=%H -- runbooks/newl1-block-times-120m/RUNBOOK.md)"
git -C benchmarkoor rev-parse HEAD             # record for the report
git -C benchmarkoor merge-base --is-ancestor 02c4809b8772274033a6a69084288e5f18b9cd9c HEAD && echo "driver code present"
git -C benchmarkoor status --porcelain --untracked-files=no | wc -l   # must print 0
export BUNDLE="$WORK_DIR/benchmarkoor/runbooks/newl1-block-times-120m"
echo "9e305c06b2a5ec3597f471afeff5f4ef8b43a7be9fa66988e00f4a922dbc568c  $BUNDLE/workload.json" | sha256sum -c

# Controller.
make -C benchmarkoor build-core
benchmarkoor/bin/benchmarkoor version          # "commit:" must be a prefix of the HEAD recorded above

# Worker image, built from the pinned NewL1 commit. A build with no Docker cache
# took 2 min 12 s on the reference machine (32 threads); fewer cores take longer.
git clone -b feat/osaka-block-compute-worker https://github.com/bnb-chain/bnbchain-newL1
git -C bnbchain-newL1 checkout --detach 049da5255b63f1729151a09be2bf48e5d917a440
git -C bnbchain-newL1 status --porcelain --untracked-files=no | wc -l   # must print 0
docker build -f benchmarkoor/Dockerfile.compute-worker-newl1 \
  -t benchmarkoor-compute-worker-newl1:049da525 bnbchain-newL1
export WORK=$(docker image inspect --format '{{.Id}}' benchmarkoor-compute-worker-newl1:049da525)
echo "$WORK"                                   # record for the report
docker run --rm --entrypoint sha256sum "$WORK" /usr/local/bin/newl1-bench
```

The last command prints the worker binary's sha256. Record whether it equals the
reference `964dbfaba2dea48ac5392c5fcb8cdb8982f3f9ede9188a38bbdfb34c8afa26af`.
The reference machine rebuilt the image from scratch and got the same sha256, so
the build is reproducible. A match means both machines run byte-identical code.
A mismatch is not a failure; continue and report it, because the timings then
compare builds as well as machines.

## 4. Run

Start the driver in a detached `tmux` session, never as a foreground or
background command of your own shell tool. A tool timeout kills whatever it
started, and an interrupted capture starts over from the beginning. The
environment goes in a file, so every start uses identical values:

```bash
cd "$WORK_DIR"
cat > "$WORK_DIR/campaign.env" <<EOF
RUN_HOME=$WORK_DIR/runs/newl1-120m
WORKLOAD=$BUNDLE/workload.json
WORK=$WORK
MEMORY=24g
BUNDLE=$BUNDLE
EOF
cat "$WORK_DIR/campaign.env"                   # WORK must be a sha256:... image ID
mkdir -p "$WORK_DIR/runs/newl1-120m"
tmux new-session -d -s newl1-block-times \
  "cd '$WORK_DIR' && set -a && . ./campaign.env && set +a && benchmarkoor/scripts/compute/run_newl1_block_times.sh 2>&1 | tee -a \"\$RUN_HOME/driver.log\"; exec bash"
```

What happens, each step announced by a `=== <UTC time> ...` line:

1. `preflight` checks the checkout, controller, image, and workload, then records
   host facts in `runs/newl1-120m/host/`.
2. `capture 67 cases` runs sessions `diagnostic-00`, `pilot-00`–`07`, and
   `qualification-00`–`07`: 3,819 samples in total. It took 66 minutes on the
   reference machine. A slower CPU takes proportionally longer.
3. `block times` writes `runs/newl1-120m/block-times.csv`.
4. The last line is `=== <time> complete: <run dir>`.

Check progress with short, read-only commands. Do not attach to the session with
a blocking command:

```bash
grep '^===' "$WORK_DIR/runs/newl1-120m/driver.log"
for s in "$WORK_DIR"/runs/newl1-120m/runs/compute-*/sessions/*/; do
  echo "$(basename "$s") $(cat "$s/samples.jsonl" 2>/dev/null | wc -l)"; done
```

Finished sessions hold 67 samples (`diagnostic`, `pilot`) or 402
(`qualification`, one warmup plus five timed runs per block).

## 5. Resuming

If the machine reboots, the tmux session dies, or the driver fails for a
transient reason (OOM, full disk, Docker restart), fix the cause, remove leftover
worker containers, and start the same `tmux` command from section 4 again:

```bash
docker ps -a --filter name=benchmarkoor-compute- --format '{{.ID}} {{.Names}}'
docker rm -f <those IDs>
tmux kill-session -t newl1-block-times 2>/dev/null
```

A finished capture is never timed again; rerunning only rewrites
`block-times.csv`. An interrupted capture starts over in a new
`runs/compute-*` directory, and the partial one stays in place, unused.

## 6. Known failure modes

| Symptom | Meaning | Action |
|---|---|---|
| `git clone` of bnbchain-newL1 asks for credentials or returns 404 | No read access to the private NewL1 repo | Stop and report |
| `docker build` fails fetching crates or git dependencies | No network access to crates.io or GitHub from Docker builds | Stop and report the failing step |
| `docker build` killed, or `rustc` exits with signal 9 | The build ran out of memory | Stop and report `free -g` |
| `make build-core` fails downloading modules or the Go toolchain | No network access to proxy.golang.org | Stop and report the error |
| `make build-core` fails with a cgo or `gcc` error | C compiler missing | Install `gcc` (for example `build-essential`), then retry |
| `bin/benchmarkoor is missing or not built from ...` | Controller absent or stale | `make -C benchmarkoor build-core`, then restart |
| `benchmarkoor checkout has local changes` | A file in the checkout changed | Stop and report `git -C benchmarkoor status` |
| `worker image ... is not loaded` | `WORK` in `campaign.env` is wrong | Stop and report `campaign.env` and `docker images` |
| `WORKLOAD differs from the one this run home started with` | The workload file changed | Stop and report both sha256 sums |
| `controller exited N; samples kept in ...` | Some samples failed | Stop. Report the tail of `capture.log`, the sample status counts from section 7, and `block-times.partial.csv` |
| Worker exit code 137 or `oom_killed` | A worker session ran out of memory | Stop and report `free -g` |

## 7. Deliverables

After `complete`:

```bash
cd "$WORK_DIR"
set -a && . ./campaign.env && set +a
RUN=$(cat "$RUN_HOME/capture.done")
python3 - "$RUN/samples.jsonl" "$RUN_HOME/block-times.csv" "$BUNDLE/reference-block-times-ryzen9950x.csv" <<'PY'
import collections, csv, json, math, sys
samples = [json.loads(line) for line in open(sys.argv[1])]
print("samples:", len(samples), dict(collections.Counter((s["phase"], s["status"]) for s in samples)))
here = {r["case_id"]: r for r in csv.DictReader(open(sys.argv[2]))}
ref = {r["case_id"]: r for r in csv.DictReader(open(sys.argv[3]))}
rows = sorted(here.values(), key=lambda r: -float(r["median_ms"]))
print("| operation | case | calls | median ms | x 200 ms slot | reference ms | this / reference |")
print("|---|---|---|---|---|---|---|")
ratios = []
for r in rows:
    name = r["case_id"].split("::")[1].split("[fork_Osaka--")[0] + "[" + r["case_id"].split("[fork_Osaka--")[1].split("-benchmark-gas")[0] + "]"
    median, reference = float(r["median_ms"]), float(ref[r["case_id"]]["median_ms"])
    ratios.append(median / reference)
    print(f"| {r['target_operation']} | {name} | {r['calls']} | {median:.1f} | {median / 200:.2f} | {reference:.1f} | {median / reference:.3f} |")
print(f"cases over one 200 ms slot: {sum(float(r['median_ms']) > 200 for r in rows)} of {len(rows)}")
print(f"geometric mean this / reference: {math.exp(sum(map(math.log, ratios)) / len(ratios)):.3f} (min {min(ratios):.3f}, max {max(ratios):.3f})")
PY
```

Then write `$WORK_DIR/REPORT.md` with:

1. Host: CPU model, cores and threads, CPU flags, RAM, kernel, Docker version,
   governor and boost state (from `runs/newl1-120m/host/`), and everything else
   that ran on the machine during the capture.
2. Inputs: the benchmarkoor HEAD, the NewL1 commit, the worker image ID, the
   worker binary sha256 and whether it matches the reference, and
   `runs/newl1-120m/host/provenance.txt`.
3. Timeline: the worker build duration, then every `===` line from
   `driver.log`, with durations.
4. Samples: the status counts printed above. Every sample should be `executed`.
5. Block times: the full table printed above, the count of cases over one slot,
   and the geometric-mean ratio against the reference machine.
6. Anomalies: every restart, warning, retry, or deviation from this runbook.
7. Appendix: the full contents of `runs/newl1-120m/block-times.csv`.

Results can't be copied off this machine, so end with the complete `REPORT.md`
in your final message, the appendix included. Leave the run home in place.
